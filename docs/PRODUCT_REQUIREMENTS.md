**已确认在 CC Switch 上二开。** 不再把“自建独立配置助手”作为另一条开发路线。桌面端承担配置写入、验证与恢复；平台 Key 页面作为可接入的入口。

本轮补充目标：在应用中提供七牛登录入口，查看自己的 Token Plan、平台 API Key，以及本机已配置到哪些工具。七牛用户侧登录方式和数据接口需验证；这与现有其他厂商的 OAuth 登录、套餐查询基础分别评估。

本文采用“桌面入口优先、七牛预设优先、Windows/macOS 优先、兼容时默认直连”的建议基线，以便评审和拆分开发。这些建议不等于用户已确认，具体待定项见第 12 节。

## 1. 背景与用户问题

用户获得 API Key 后，仍需要查找各工具的配置位置，理解服务地址、认证方式、模型名称及 JSON/TOML 等格式。写入后还可能遇到环境变量覆盖、模型不兼容、需要重启或原有设置被覆盖的问题。

CC Switch 已有供应商管理、配置切换、本地路由和深度链接基础。本次二开重点是把这些能力组织成面向新用户的完整流程，补齐验证和恢复，降低首次接入成本。

“一键配置”意味着用户不需要自己找文件、编辑配置或重复填写服务地址与模型；首次安装、应用唤起确认和必要的重启仍可能发生。

## 2. 产品目标与用户场景

### 2.1 产品目标

1. **输入少**：支持“登录七牛后选 Key”和“手动填一次 Key”两条路径；服务地址、协议和推荐模型由已验证预设提供。
2. **配置可靠**：检测环境后再写入，保留无关设置；失败不留下损坏配置，能够恢复。
3. **结果可信**：区分配置写入、接口测试和目标工具实际使用，不把导入成功当作可用。
4. **维护简单**：更新 Key、重试失败项和恢复都有明确入口；在适用条件下借助本地代理减少重启。

### 2.2 用户场景

| 用户/场景 | 用户诉求 | 产品应交付的结果 |
| --- | --- | --- |
| 首次获得 Key | 不理解配置，只想开始使用 | 按向导完成配置，知道如何在目标工具发起请求 |
| 已有七牛账号 | 查看自己的套餐与 Key，不想反复去网页复制 | 登录后展示 Token Plan 和平台 Key，选择可用 Key 配置工具 |
| 排查已配置的 Key | 想知道哪个 Key 用在哪些工具、当前是否启用 | 查看本机配置清单，并在可确认时关联所属账号和平台 Key |
| 同时使用多个工具 | 同一 Key 不想重复填写 | 一次输入、按工具生成配置并展示结果 |
| 已有配置，更换服务商或 Key | 保留个人设置，出错能回退 | 预览、备份、更新、验证和恢复 |
| 从平台 Key 页面进入 | 点击后直接配置到工具 | 唤起二开客户端，复用同一向导 |
| 客服排障 | 判断失败发生在哪一步 | 获取脱敏的检测结果、原因及恢复状态 |

### 2.3 本次不新增的能力

- 重做 CC Switch 的 MCP、Skills、提示词、会话管理等功能；已有能力继续保留。
- 新建聊天产品、模型计费系统、Key 发放系统或云端网关。
- 在客户端新增购买/续费套餐、充值、自动创建或吊销平台 Key 的操作；首版账号接入以查询、选择和配置为主。
- 在首版向导中自动安装、升级、卸载目标工具，或强制关闭用户正在运行的工具。
- 承诺任意服务商、模型、客户端版本都可使用，或所有变更都无需重启。
- 将功能直接加入 qdesk 等其他产品；本次交付范围是当前 CC Switch 二开项目。

## 3. 首版范围与优先级

P0 是首版配置闭环的必需能力；P1 是闭环后的增强。以下为建议交付基线。

| 模块 | 优先级 | 范围与边界 |
| --- | --- | --- |
| CC Switch 内“快速配置”入口 | P0 | 首页明显入口，保留现有高级管理入口 |
| 预设与一次 Key 输入 | P0 | 优先落地七牛预设；是否仅支持七牛待定 |
| 七牛登录与账号概览 | P0 建议新增 | 应用内登录入口、登录状态、账号信息、退出/重新登录；实际授权方式在 M0 验证 |
| 我的 Token Plan | P0 建议新增 | 展示账号的套餐、状态、额度、有效期和重置时间，以平台实际返回字段为准 |
| 平台 Key 与本机配置清单 | P0 建议新增 | 查询账号下的 Key；独立显示本机配置及工具绑定；支持选择已有 Key 进入向导 |
| Codex、Claude Code、WorkBuddy 适配 | P0 目标 | 三者保留在首版目标范围；每个声明支持的组合必须通过真实客户端验收 |
| 安装/版本/配置位置检测 | P0 | 识别可配置、未安装、版本未验证及冲突 |
| 预览、备份、合并、启用 | P0 | 不止新增供应商，还要明确启用结果；单工具失败可恢复 |
| 连接验证、使用引导与结果 | P0 | 新增真实模型请求测试；按工具提示生效动作 |
| 更新 Key、重复配置、重试 | P0 | 避免重复供应商和重复写入，支持仅重试失败项 |
| 配置历史与恢复 | P0 | 按操作和工具恢复，展示恢复结果 |
| Key 页面唤起客户端 | P1 建议 | 复用同一向导；页面位置和仓库待定 |
| 本地代理的快速切换体验 | P1 建议 | 优化后续 Key/上游切换和常驻状态提示，复用现有代理引擎 |
| Linux、Codex 桌面版、更多工具 | 后续验证 | 建议先交付原生 Windows/macOS 上的 Codex CLI、Claude Code 和 WorkBuddy |

**代理依赖例外**：某工具与预设上游必须经过协议转换时，代理接入、生命周期及恢复属于该组合的 P0，不能因为代理体验列为 P1 而延期。没有已验证直连或代理路径的组合不可标为支持。

**WorkBuddy 发布门槛**：核验其实际产品身份、配置方式和生效规则。若无法完成自动配置，需明确调整发布范围；只给手工教程或显示“即将支持”不算完成 WorkBuddy 的 P0。CodeBuddy CLI 的适配不能替代 WorkBuddy。

## 4. 用户流程与页面

### 4.1 桌面主流程

**打开快速配置 → 填写 Key → 选择工具 → 自动检测 → 预览变更 → 备份并应用 → 测试连接 → 查看结果并开始使用。**

检测可在进入向导后并行执行。主流程只有一次“应用配置”确认，不把每个文件的读写拆成用户必须操作的步骤。

| 页面/阶段 | 展示内容 | 主要操作与规则 |
| --- | --- | --- |
| ① 填 Key、选工具 | 预设服务商、Key 输入框、工具卡片、安装与版本状态 | Key 默认隐藏，可临时显示；至少选一个就绪工具；有多个预设时可切换 |
| ② 检测与预览 | 各工具的服务商、模型、当前配置摘要、变更项、直连/代理方式、重启要求 | 无关配置保留；配置路径折叠展示；主按钮为“应用并测试” |
| ③ 应用中 | 每个工具的备份、写入、启用、测试进度 | 防止重复提交；可停止后续步骤，进行中的写入需完成或恢复后才能结束 |
| ④ 结果 | 逐工具展示配置、连接、使用验证状态；失败原因和下一步 | 打开工具/查看启动方法、重新测试、修改 Key、恢复本次配置 |
| ⑤ 配置历史 | 时间、工具、预设、脱敏变更摘要、备份及恢复状态 | 查看详情；恢复指定工具的本次变更 |

预览页说明：“连接测试会发送少量测试请求，可能消耗 API 额度。”测试使用固定短提示，不读取或上传用户项目内容。

### 4.2 异常分支

- **未安装**：展示获取方式与“重新检测”；允许继续配置其他就绪工具，不把写出文件视为安装成功。
- **版本未验证或位置不明确**：暂停该工具自动写入；多个安装实例时让用户选择目标实例。
- **已有配置**：预览将替换的供应商、模型和凭据类型；保护原登录信息，提供恢复入口。
- **配置被覆盖**：说明环境变量、项目设置或管理策略的影响；不默认删除全局变量或项目设置。无法确认生效配置时不宣称已可用。
- **部分失败**：成功工具保留结果，失败工具独立重试或恢复，不用总的“成功”掩盖失败。
- **写入后测试失败**：保留“已写入、测试未通过”的状态，提供修改、重测、恢复；不因网络故障自动撤销其他成功工具。

### 4.3 Key 页面入口（P1）

用户点击“一键配置”，页面唤起二开客户端并带入已知服务商与工具信息，进入同一检测与预览流程。参考 sub2api 的导入体验，不预设沿用其具体实现。

未安装、浏览器拦截、导入过期或无法取得完整 Key 时，提供安装、重新唤起或手动粘贴 Key 的路径。普通网页不直接写本机配置；点击成功不等于配置完成。

页面不要求用户重复选择已有明确值；客户端仍展示变更预览。二开版协议注册及原版共存策略在接入前确定，避免唤起错误应用。

### 4.4 七牛账号入口与 Key 管理

新增入口“七牛账号”，包含账号概览、“我的 Token Plan”“平台 API Key”“本机已配置”四部分。登录只是可选的凭据获取与账号查询方式，已有 Key 的用户仍可直接配置。

**应用内点击登录七牛 → 完成七牛登录/授权 → 读取账号、套餐和 Key 列表 → 选择 Key → 选择工具 → 进入同一预览、备份、应用与验证流程。**

“应用内登录入口”不预设必须内嵌网页；使用七牛支持的登录/授权方式，并在完成后回到客户端。仅打开控制台网页不算完成账号接入，平台会话凭据也不直接当作模型 API Key。

| 页面区域 | 需要展示的信息 | 用户操作与边界 |
| --- | --- | --- |
| 账号概览 | 账号身份、登录状态、最近同步时间 | 登录、刷新、重新登录、退出；查询失败与未登录分开展示 |
| 我的 Token Plan | 套餐名称/类型、有效状态、适用模型或服务、总量/已用/剩余、有效期及重置时间（平台有返回时） | 多套餐分别展示，不合并不同单位或周期的额度；无套餐、未知、查询失败是不同状态 |
| 平台 API Key | 账号名下 Key 的名称、稳定 ID、脱敏标识、可用状态及所属套餐/项目（平台可提供时） | 选择 Key 配置、刷新或打开控制台；不能因为登录成功就假定能重新取回历史 Key 明文 |
| 本机已配置 | 本地供应商/Key 的脱敏标识、工具、模型、启用状态、来源，以及可确认的账号/平台 Key 关联 | 查看详情、测试、配置到其他工具、更新或恢复；本地记录不等于云端所有 Key |

平台只返回脱敏 Key 时，允许展示和关联该记录，但配置必须使用已安全保存的对应完整 Key，或让用户粘贴。未确认映射的本地 Key 标为“未关联”，不能只凭名称或尾号判断相同，也不能默认上传全部本地 Key 来比对。

套餐过期、额度不足或 Key 不可用时显示原因；不自动改用按量计费端点。套餐查询失败不影响已有有效 Key 的配置能力，也不把缓存数据当成刚同步的结果。

## 5. 功能要求

### 5.1 预设与 Key

| 编号 | 要求 | 验收边界 |
| --- | --- | --- |
| F01 | 按工具提供预设，包含地址、认证方式、协议、推荐模型、代理依赖 | 用户无需手填 URL 或模型 ID；仅开放已验证组合 |
| F02 | 同次输入的 Key 应用到多个工具，各工具可使用不同模型 | 不重复粘贴；不从 Key 外形猜服务商；权限不足逐工具报错 |
| F03 | 校验空值和首尾空白，Key 默认脱敏 | 格式校验不代替接口认证；取消未提交向导不新增持久化凭据 |
| F04 | 预设有稳定标识与版本；模型不可用时提供已验证选项或阻断 | 不静默更换模型，不假设所有 Key 拥有同样权限 |

建议首版预设随客户端发布，在线更新后续扩展。实际端点、模型 ID 和权限在适配阶段核实，本文不填入未经验证的生产参数。

### 5.2 检测、写入与启用

| 编号 | 要求 | 验收边界 |
| --- | --- | --- |
| F05 | 识别工具、安装位置、版本、实际配置目录及可写性，尊重已支持的自定义目录 | 区分“未找到命令”与“确定未安装”；不确定时允许重新检测或定位 |
| F06 | 检查可能覆盖配置的环境变量、项目设置和管理策略 | 展示可确认冲突；不声称能检测当前进程看不到的所有环境 |
| F07 | 写入前预览变更摘要；取消后配置与启用状态不变 | Key 脱敏；不要求用户读懂 JSON/TOML |
| F08 | 每次修改前保存可恢复快照，覆盖目标文件、相关供应商记录和启用状态 | 定时数据库备份不替代本次操作备份；记录原文件是否存在 |
| F09 | 合并必要字段、保留无关设置；按单工具执行可恢复的写入与启用 | 多文件和相关管理状态须一致恢复；备份失败不写入该工具 |
| F10 | 写入前复核是否有并发修改，写入后校验格式和预期字段 | 有新改动则重新预览，不覆盖；失败不留半份配置 |
| F11 | 保存供应商后明确执行或确认启用，同步 CC Switch 活动状态 | 不能只新增数据库记录就显示目标工具配置成功 |
| F12 | 重复配置复用本向导创建的对应记录；更新 Key 时明确影响目标 | 用预设标识、工具和管理记录关联，不按名称覆盖用户自建记录 |

完全相同的配置跳过无意义写入，并允许重新测试。更新 Key 时预览影响的工具，本次未选工具保持原状态。进程中断后，下次启动应识别未完成操作并提供一致恢复路径。

### 5.3 连接测试与使用验证

当前代码的 `StreamCheckService` 仅检测地址可达性，收到 HTTP 401、403 或 500 也可判定为“可达”，不验证 Key 或模型。因此本次必须新增真实模型请求验证，不能直接把现有连通检测结果改名为“可用”。

| 层次 | 允许展示的结论 | 所需依据 |
| --- | --- | --- |
| 配置完成 | “配置已写入/已启用” | 写入、解析、预期字段核验通过，相关活动状态一致 |
| 接口通过 | “连接测试通过” | 用本次 Key、实际模型、选定链路完成最小模型请求，核验所需流式返回 |
| 工具可用 | “目标工具实测通过” | 真实目标工具在该环境请求成功，并有可归属本次配置的结果依据 |

| 编号 | 要求 | 验收边界 |
| --- | --- | --- |
| F13 | 使用本次实际默认模型和链路进行真实模型请求测试 | 不用替代测试模型的成功代替默认模型；代理模式测试需经过本地代理 |
| F14 | 检测认证、有效模型输出及所需协议能力 | 地址可达、模型列表可读或 HTTP 200 不能单独作为成功依据 |
| F15 | 测试有超时、进度和可控重试 | 建议每工具自动测试一次、45 秒超时；失败后手动重试，避免无限计费；这是新增测试的建议值 |
| F16 | 提供启动/重启引导和最小验证任务 | 无自动客户端证据时显示“待在工具中验证”；手工反馈标为“用户确认可用” |
| F17 | 分别记录配置、连接、重启待办和工具使用状态 | 部分成功、跳过测试、测试失败不得汇总成“全部可用” |

发布验收在隔离测试目录中完成真实客户端请求，覆盖流式响应和一次只读工具调用（适用于具备该能力的工具）。用户日常自检不自动运行项目命令，不以聊天成功推断全部工具调用兼容。

### 5.4 恢复与错误处理

| 编号 | 要求 | 验收边界 |
| --- | --- | --- |
| F18 | 按工具恢复本次修改前的配置与启用状态 | 恢复后重新解析并提示生效动作；原不存在的文件仅在确认安全时移除 |
| F19 | 恢复前检测后续修改，并备份当前状态 | 存在后续修改时展示冲突，不能用旧整文件覆盖无关新设置 |
| F20 | 错误给出阶段、中文原因、建议操作和脱敏详情 | 恢复失败必须明确标识，保留备份位置和下一步；不输出凭据 |

| 情况 | 用户提示方向 | 后续操作 |
| --- | --- | --- |
| Key 无效、过期或权限不足 | “认证失败，请检查 Key 或权限” | 修改 Key、重测 |
| 额度不足或限流 | 根据明确响应区分“额度不足”和“请求过于频繁” | 查看平台、稍后重试 |
| 模型不存在或无权访问 | “当前 Key 无法使用所选模型” | 选择已验证模型、核对权限 |
| 网络、DNS、TLS、超时 | “未能完成连接测试”并说明失败阶段 | 检查网络、重试，不直接判定 Key 错误 |
| 地址或协议不匹配 | “该配置与目标工具所需接口不兼容” | 检查预设，使用已验证的代理路径 |
| 不可写、格式损坏或并发修改 | “配置未应用”或“已恢复到修改前” | 处理权限/冲突、重新检测 |
| 代理未启动或端口占用 | “本地代理未就绪，无法启用该配置” | 重试、处理端口；有兼容路径时才提供直连 |

无法确认原因时保留“不确定”状态，展示脱敏详情，不把所有失败归因于 Key。

### 5.5 七牛账号、套餐和 Key

| 编号 | 要求 | 验收边界 |
| --- | --- | --- |
| F21 | 提供七牛登录入口并获得可用于当前用户数据查询的登录态 | 登录取消、失败、过期有明确状态；完成网页登录但客户端未取得有效授权时，不显示接入成功 |
| F22 | 获取并显示当前账号的 Token Plan/套餐信息 | 用量单位、统计周期、更新时间明确；缺失字段显示未提供，不伪装为零额度或无限额度 |
| F23 | 查询账号名下 API Key，支持多条记录及平台存在时的分页 | 名称、ID、脱敏标识、状态按实际字段展示；云端空列表和查询失败区分 |
| F24 | 从平台 Key 列表选择凭据进入快速配置，自动带入已验证预设 | 有完整可用凭据时不重复粘贴；只有脱敏值时明确要求补充，不尝试把脱敏值写入工具 |
| F25 | 展示本地已有配置和工具绑定，可在有可靠依据时关联平台记录 | 不把本地配置冒充平台 Key 清单；不因刷新远端列表就删除本地配置 |
| F26 | 根据可确认的套餐/Key 类型匹配服务端点与模型 | 区分套餐和按量服务；没有可靠依据时提示确认，不静默更改计费路径 |
| F27 | 支持刷新、会话过期后重新登录和退出账号，隔离不同账号数据 | 退出清除账号查询会话与相关缓存，不擅自吊销平台 Key 或删除工具配置；说明已有配置是否仍保留 |
| F28 | 同步失败保留带时间标识的最近结果，并允许重试 | 不使用缓存宣称实时额度；套餐查询失败不阻断手动 Key 路径；展示账号查询与模型请求各自错误 |

首版建议只激活一个七牛账号，允许退出后切换；是否需要同时管理多个七牛账号列为待定。账号查询走面向当前用户的接口，不把内部管理后台或管理员凭据作为客户端依赖。

## 6. 工具适配与生效规则

| 工具 | 建议首版对象 | 必须确认的事项 | 生效提示要求 |
| --- | --- | --- | --- |
| Codex | Codex CLI | 凭据来源、配置位置、活动 provider、模型和接口；桌面版单独验证 | 首次接入及外部修改按适配结果提示重启 CLI，不承诺当前会话立即加载 |
| Claude Code | 已验证版本 | 认证、模型映射、环境变量优先级、流式和工具调用能力 | 复用既有切换机制，仅对验证过的变更标注无需重启 |
| WorkBuddy | 实际 WorkBuddy 客户端 | 配置入口、可自动写入方式、凭据保存、协议和加载时机 | 实测前不承诺热更新，不假设有公开导入协议 |

维护“系统/架构 × 工具及版本 × 预设版本 × 模型 × 直连/代理”的兼容性记录。发布时列出具体通过的组合；CC Switch 支持某个平台不等于本次三工具组合已经通过。Windows 原生、WSL、容器和远程环境分别验收。

### 6.1 本地代理规则

建议支持直连的组合默认直连，需要转换协议时明示开启代理。用户主动选择代理以减少后续切换成本时，复用现有本地路由。

| 场景 | 要求 |
| --- | --- |
| 首次接入 | 先确认代理健康，再备份并接管配置；明确工具需要的加载动作 |
| 仅修改代理上游 Key/供应商 | 工具配置、模型及协议能力保持兼容时，新请求使用新上游；进行中的请求不迁移 |
| 修改模型、映射或工具配置 | 重新判断是否需重启，不沿用“切 Key 无需重启”的结论 |
| 关闭窗口或退出进程 | 区分托盘常驻与完全退出；完全退出时复用并核验停止/恢复机制，说明进行中的请求可能中断；恢复失败保留备份、显示失败及处理入口 |
| 代理异常或开机后未启动 | 下次启动检测未完成恢复及失效代理配置，显示未就绪与恢复入口，不把占位凭据当有效直连配置 |
| 关闭代理或恢复 | 区分“当前供应商改为直连”和“恢复本次操作前配置”；只有兼容时提供前者 |

代理切换以“新的真实请求到达预期上游”为验收依据。上游不支持直连时，提供保持代理运行或恢复原可用配置的选择，不承诺自动降级直连。

## 7. 数据、凭据与发行要求

| 对象 | 保留信息 | 约束 |
| --- | --- | --- |
| 预设 | ID、版本、工具映射、地址、认证、模型、代理依赖、兼容性记录 | 与用户 Key 分离，不静默切到未验证上游 |
| 配置操作 | 操作 ID、时间、选中工具、原/目标供应商、阶段、脱敏结果 | 支持恢复与排障，不把 Key 写入诊断日志 |
| 操作快照 | 原配置、文件存在状态、相关供应商记录及启用状态 | 与凭据同等级保护，限制本机访问，不随诊断报告导出 |
| 验证记录 | 工具/版本、预设/模型、模式、时间、失败类别、结果来源 | 区分接口测试、客户端观测与用户确认 |
| 七牛账号与套餐缓存 | 账号稳定 ID、登录状态、套餐字段、同步时间 | 登录会话与模型 API Key 分开保护；账号切换不能串用缓存 |
| 平台 Key 关联 | 云端 Key ID、脱敏展示、可确认的本地供应商/工具绑定 | 不假定列表接口返回明文；不上传本地 Key 进行无依据的关联 |

- 按目标工具实际能力保存凭据；需要明文文件时不宣称全程加密存储。取消未提交向导清理临时凭据。
- Key、认证头、含凭据的 URL 不进入遥测、诊断剪贴板文本、普通错误日志或源码；导出诊断前脱敏。
- 备份可能包含历史 Key，提供查看和删除入口及保留策略；常规备份轮转不能无提示清除仍需恢复的操作快照。
- 网页入口不默认把完整 Key 拼入持久 URL。建议使用短时单次导入凭据换取配置，或退回客户端粘贴；Base64 不作为加密方案。具体方式在 P1 设计确定。
- 快速配置不新增强制注册或云端存储 Key 的前置条件；不因使用向导自动启用现有云同步。
- 自有品牌发行需明确应用标识、数据目录、协议注册和更新渠道；原版数据迁移有预览、备份与回退，不默认共用数据库。
- 保留项目和依赖要求的版权及许可声明；二开源码是否公开、收费和品牌另行决策。

## 9. 验收标准

**总验收口径：在声明支持的系统、工具版本和预设组合上，用户通过向导配置后，能在真实目标工具成功发起请求；无关配置保留；失败原因明确；可以恢复。**

| 用例 | 场景 | 通过标准 | 对应要求 |
| --- | --- | --- | --- |
| A01 | 新用户配置一个工具 | 输入 Key、选工具即可写入并启用；无需编辑文件；真实客户端请求成功 | F01–F05、F11、F13–F17 |
| A02 | 同时配置三个目标工具 | Key 只填一次；逐工具报告；三个声明支持组合各自完成真实请求 | F02、F05、F09、F17 |
| A03 | 已有个人配置 | 仅变更预览字段，MCP 等无关配置语义保持一致；备份可读取 | F07–F09 |
| A04 | 重复应用与更新 Key | 不产生重复记录或无意义写入；更新只影响选定工具 | F12 |
| A05 | Key/模型/额度/网络错误 | 不显示全部可用；原因和操作建议准确；可修改重测 | F13–F17、F20 |
| A06 | 未安装、未知版本、多实例、配置覆盖 | 明确说明，仅就绪工具继续；不确定目标不自动覆盖或标记可用 | F05–F07 |
| A07 | 备份失败、写入失败、进程中断 | 备份失败不写；异常后可一致恢复；下次启动识别未完成操作 | F08–F10、F18、F20 |
| A08 | 预览后文件被外部修改 | 检测变化并重新预览，不覆盖新内容 | F10 |
| A09 | 恢复，包括恢复前又有用户修改 | 恢复原活动状态；后续无关改动不被覆盖；冲突有处理入口 | F18–F19 |
| A10 | 多工具部分失败 | 成功结果保留；只重试失败目标，不重复更改成功工具 | F09、F12、F17 |
| A11 | 配置需重新加载 | 显示对应工具动作；未验证前不标实测通过 | F16–F17、第 6 节 |
| A12 | 默认模型、流式和工具调用 | 发布组合通过短对话、流式、一次只读工具调用；上游/模型符合预设 | F13–F16 |
| A13 | 代理接入、切 Key、退出及故障 | 先健康再接管；后续请求到新上游；异常/退出有明确恢复路径 | 第 6.1 节；依赖代理的组合为 P0 |
| A14 | 网页导入及失败兜底 | 安装、唤起、过期、重复点击均有路径；导入不绕过预览 | 第 4.3、7 节；P1 |
| A15 | 日志、界面、诊断导出 | 不泄露完整 Key、认证头或快照凭据；可区分验证来源 | F03、F20、第 7 节 |
| A16 | 七牛登录、取消、过期、退出及切换账号 | 正确显示状态；重新登录可恢复查询；不同账号数据隔离；不擅自删除工具配置 | F21、F27 |
| A17 | 有套餐、无套餐、多套餐及查询失败 | 额度单位、周期、有效期及数据时间准确；缺失/失败不显示为零；不自动改为按量服务 | F22、F26、F28 |
| A18 | 平台 Key 清单与本机已有配置 | 完整呈现接口可返回的记录；云端和本地来源清楚；未关联记录不误绑；刷新不删除本地配置 | F23、F25 |
| A19 | 从账号选择 Key 配置 | 有完整凭据时直接进入原配置闭环；仅有脱敏信息时要求补充；套餐与端点匹配 | F24、F26、A01–A02 |

发布前，所有声明支持组合的 P0 用例必须通过。未通过组合只能标为未支持，并同步调整发布范围；“部分失败可解释”不能替代三工具目标验收。

## 10. 效果指标

内测先建立基线，再制定转化和耗时目标，不承诺未经测量的“几秒完成”。按工具统计，并单独观察多工具全部成功率。

| 指标 | 计算口径 | 用途 |
| --- | --- | --- |
| 配置完成率 | 写入并启用的工具任务数 / 点击应用后创建的工具任务数 | 判断配置可靠性 |
| 接口通过率 | 测试通过数 / 实际发起测试数 | 判断预设和服务可用性 |
| 首次使用成功率 | 有目标工具成功证据的任务数 / 已应用配置的任务数 | 判断实际使用；不可观测样本列为未知并报告覆盖率 |
| 首次成功耗时 | 已安装助手及目标工具的用户，从进入向导到可观测首次成功 | 记录中位数及 P90；安装耗时另计 |
| 恢复成功率 | 恢复核验通过数 / 发起恢复数 | 判断可恢复性 |
| 失败分布 | 按检测、备份、写入、认证、模型、网络、代理、加载分类 | 决定改进优先级 |

首版可用本地脱敏记录和内测记录统计，不以新增云端埋点系统为前置依赖。用户手工确认与自动观测成功分开统计。

## 12. 决策记录与待定项

### 12.1 已确认

- 在当前 CC Switch 项目上二开。
- 核心体验是登录后选 Key 或手动填一次 Key、选择工具，由产品预设服务地址与模型。
- 补充七牛登录、自己的 Token Plan、平台 Key 和本机已配置清单的产品目标；首版批次和接口能力仍需确认。
- 目标工具为 Codex、Claude Code、WorkBuddy，其他工具后续扩展。
- 保留无关配置，明确失败原因、生效动作，支持恢复。
- 本轮先完成 PRD，不开始功能开发。

| WorkBuddy 适配不及时的发布策略 | 明示阻塞后调整范围，不悄悄删除目标或用手工步骤替代验收 | M1 发布范围确认前 |
| Key 页面与凭据交接 | 明确平台、仓库、完整 Key 获取能力，再选择单次凭据或粘贴 | M2 开发前 |
| 品牌、开源、收费及分发 | 暂称“AI 工具快速配置”；二开与源码是否公开分别决策 | 对外发行前 |
