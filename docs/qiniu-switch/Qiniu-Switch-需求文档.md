Qiniu Switch 需求文档

版本 v1.0 · 2026-09-28
依据：现有产品需求稿、当前工作区代码及用户提供的四张截图。本文为需求与现状整理，不作为上线验收证明。

## 1. 背景与目标

用户获得七牛模型 API Key 后，仍需查找不同 AI 工具的配置位置、服务地址、认证方式和模型名称。配置完成后，用户还需要判断是否启用、是否能实际调用，以及去哪里查看用量与失败原因。

本项目在 CC Switch 基础上开发 Qiniu Switch。目标是让用户通过一次凭据输入或网页导入，完成目标工具配置，并在客户端获得必要的查询和排障入口。首批目标工具为 Claude Code、Codex、WorkBuddy；支持范围以真实客户端验收结果为准。

## 2. 用户问题与解决方式

| 原有问题 | 需求 | 本轮修改及作用 |
| --- | --- | --- |
| 配置字段多，容易填错 | 减少重复输入，使用七牛预设 | 导入时带入供应商、端点与 Key，减少手动复制和填写。 |
| 网页 Key 与桌面工具割裂 | 从 Key 页面直接进入配置 | 增加本地演示页导入按钮和客户端唤起流程，验证入口衔接。 |
| 不知道应该导入哪个工具 | 可选择目标工具并适配配置 | 导入弹窗增加目标选择，按预设调整端点，降低选错配置的可能。 |
| 模型名称需要手填 | 从接口返回列表选择模型 | 动态获取模型并要求选择后再导入，减少模型 ID 拼写错误。 |
| 用量与失败原因查询分散 | 提供统一查询入口 | 新增 AK/SK 接入及 Key、配额、账单、用量和日志查询能力。 |
| 无法确认修改是否生效 | 区分导入、启用与实际可用 | 明确各阶段验收口径；完整验证与恢复闭环仍需补齐。 |

## 3. 使用对象与范围

面向首次接入七牛的开发者、使用多个 AI 工具的用户，以及协助排障的支持人员。本轮以配置导入和只读查询为主，不新增聊天产品、充值购买、平台 Key 创建或吊销、目标工具自动安装等能力。

## 4. 功能需求与验收标准

状态口径：“已有实现”表示代码中存在相关能力；“本地演示”表示截图与 Mock 页可展示流程；“待补齐/验收”表示尚不能据此承诺生产可用。

| 编号 / 需求 | 验收标准 | 当前状态 |
| --- | --- | --- |
| R01 七牛品牌与独立入口 | 使用 Qiniu Switch 名称、应用标识和专属唤起协议；避免唤起原版。 | 已有实现；安装包共存需实测。 |
| R02 网页导入 | 点击对应 Key 后唤起客户端，展示正确供应商信息；用户可取消。 | 本地演示；正式控制台接入待完成。 |
| R03 目标工具与配置预览 | 展示目标工具、供应商、端点及脱敏 Key；切换工具后更新配置并重选模型。 | 已有实现；逐工具兼容性待验收。 |
| R04 模型列表与选择 | 使用当前 Key 获取列表；失败可重试；空列表或未选模型时阻止导入。 | 已有实现；模型列表不等于调用验证。 |
| R05 管理接口认证 | 支持连接、状态查询、断开；认证失败有提示；断开后停止使用会话凭据。 | 已有 AK/SK 实现；不是网页登录。 |
| R06 用量和账单查询 | 支持 Key/配额、月账单、区间账单、日志及详情、用量、计费项、模型市场；区分错误与空数据。 | 已有查询实现；业务字段逐项联调验收。 |
| R07 安全配置与恢复 | 检测安装和冲突；预览、备份、合并、启用；失败按工具恢复；重复操作不产生无意义记录。 | 完整快速配置流程待补齐/验收。 |
| R08 真实可用性验证 | 以选定 Key、模型和链路完成真实请求，分别记录配置、接口和目标工具结果。 | 需专项验收，不能以导入成功代替。 |
| R09 七牛账号与套餐 | 获得有效用户授权，显示账号和 Token Plan；平台 Key 与本机配置按可靠依据关联。 | 需求保留；当前 AK/SK 查询不能替代。 |

## 5. 已解决问题的表述边界

本轮已提供减少配置输入、选择目标工具、动态选择模型和集中查询的实现基础，并形成网页到桌面导入的本地演示。当前没有提供配置耗时、成功率、用户规模等统计，因此不宣称量化提升。

## 6. 用户流程与异常处理

### 6.1 当前导入流程

本地 Key 演示页点击“导入 Qiniu Switch” → 浏览器确认打开应用 → 客户端预览配置 → 选择目标工具 → 获取并选择模型 → 确认导入供应商。当前演示链接设置 enabled=false，因此导入后不能直接显示“已启用”或“工具可用”。

### 6.2 管理查询流程

输入七牛管理 AK/SK → 连接并验证 Key 列表查询 → 选择查询类型与参数 → 展示结果或错误 → 断开。管理 AK/SK 用于管理接口；模型 API Key 用于模型调用，二者不能混用。

### 6.3 目标完整流程（待补齐/验收）

选择凭据及工具 → 检测安装、配置目录和冲突 → 预览变更 → 保存快照 → 合并写入并启用 → 真实请求测试 → 查看逐工具结果 → 必要时重试或恢复。

| 异常场景 | 产品应有行为 |
| --- | --- |
| 未安装、浏览器未能唤起 | 提供安装或重新唤起入口，以及手动填写 Key 的替代路径。 |
| 模型获取失败或无结果 | 显示对应状态，允许重新获取；保持导入不可提交。 |
| 只有脱敏 Key | 允许展示记录；配置前补充完整 Key，不能把脱敏字符串写入工具。 |
| 认证失效、网络异常、查询失败 | 展示明确错误，区分凭据错误与网络失败；不伪装为空数据或零用量。 |
| 配置写入成功但测试失败 | 显示“已写入、测试未通过”；保留重试和恢复入口。 |
| 多工具部分失败 | 逐工具展示结果，成功项保留；失败项独立重试或恢复。 |

## 7. 后续验收重点

优先完成三类验证：① Windows/macOS 的安装、唤起和逐工具真实调用；② 写入、启用、重复配置及恢复的一致性；③ 正式控制台凭据交接与查询接口联调。网页登录和 Token Plan 需先核实授权及数据接口，再确定实现方案。

本次文档整理未执行生产接口请求、目标工具真实调用或兼容性测试。原需求稿见 docs/PRODUCT_REQUIREMENTS.md；本版补充现状与验收边界，不替换原稿。
